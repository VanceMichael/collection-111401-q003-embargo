# 定时开放资料的可校准领取

按发布方排期定时领取场次资料：持续校准来源逻辑时钟，确认某场次确实开放后才领取对应排期版本；顺延、取消或暂时无法确认的场次都保留明确状态。内置逻辑时钟用来演练开放时间变化，不需要等待真实发布场次。

## 运行

使用 Node.js 22。依赖版本已锁定，运行、测试和演示不下载任何数据或软件。运行时只使用 Node.js 内置模块。

- `npm test`：执行本地来源交互、定时领取及收件存储测试。
- `npm run build`：逐个检查模块语法。
- `npm run demo`：启动本地来源，运行定时领取演练（开放、取消、顺延、重启），打印真实收件结果后退出。
- `npm start`：在 127.0.0.1:8080 启动本地来源，PORT 可调整。`GET /health` 返回服务与当前来源版本；原有 `/_health` 仍可使用。

容器方式：`docker build -t collection-embargo .`，然后 `docker run --rm --network none collection-embargo`。镜像构建属于环境准备，运行时不访问公网。

## 项目结构

`src/domain.mjs` 提供业务入口：人工读取 `receiveCurrent` 与定时领取 `collectScheduled`。`src/scheduler.mjs` 持续校准来源时间依据、跟踪排期变化，仅在确认开放后领取对应版本。`src/client.mjs` 负责有限大小的原始领取；`src/archive.mjs` 保存内容及来源凭据。`provider/` 是独立的本地来源服务，`docs/source-contract.md` 说明它的资料和状态约定。演示使用临时目录，正式接入可向业务入口传入持久目录。

本地服务中的机构、记录和文件都是合成业务资料，不使用真实账号、个人信息或第三方站点数据。当前演示通常十秒内结束，全部本地测试应在六十秒内结束。

## 领取状态

每个场次的状态保存在收件目录的 `collection.json`：`pending`（等待开放确认或暂时无法确认）、`received`（已领取当前排期版本，凭据在 `receipts/`）、`cancelled`（来源已取消）。来源更换版本时，已收旧版本移入该场次的 `history`，新版本重新等待开放确认。校准信息只存在于内存：宿主单调时钟基点每次启动都不同，重启后重新向 `/time` 校准，旧计时器不会在新进程里直接触发领取。正文请求只依据有效校准证明的开放许可，不作为计时探针；各场次独立判定，顺延的场次不会阻塞其他已开放场次。
